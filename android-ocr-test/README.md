# 명함 OCR 테스트 앱

안드로이드 기기에서 Google ML Kit으로 명함을 읽고 관리자 계정으로 영업관리 DB에 등록하는 앱입니다. 인식은 기기에서 실행하며 **명함 등록**을 누르면 사진과 확인한 정보가 서버로 전송됩니다.

## 기능

- 카메라 촬영 또는 앨범 이미지 선택
- 자동 테두리 감지, 회전, 자르기, 필터 보정
- 한국어 모델과 영문 모델을 각각 실행
- 중복 줄을 제거한 통합 OCR 텍스트
- 기관명, 이름, 직책, 전화, 휴대폰, 이메일 후보 추출 및 직접 수정
- 여러 번호가 한 줄에 있을 때 전화·휴대폰·팩스를 구분하고, 띄어 쓴 이름과 `O`로 오인된 번호를 보정
- 사진의 특정 부분을 지정해 해당 필드를 다시 읽고, 인식 원문을 보면서 최종 값을 직접 확정
- 관리자 이메일·비밀번호 최초 로그인 후 명함 등록, 웹 명함관리 목록 열기
- OCR 처리 시간 표시
- 앱을 열 때 GitHub 릴리스에서 새 버전 확인, APK 다운로드 및 설치 화면 연결

3번 재테스트에서 `010.7396.1 676`으로 끊긴 휴대폰 번호를 이어서 추출합니다. 손글씨에서 이메일처럼 OCR 원문에 없는 문자는 자동으로 만들 수 없습니다. **선택 영역 다시 읽기**로 해당 줄만 읽거나 사진을 보며 직접 입력하세요. 선택 영역에서 확정한 값은 전체 사진의 다른 후보보다 우선해 해당 필드에 적용됩니다.

관리자 로그인은 앱을 다시 실행해도 유지됩니다. 갱신 토큰과 계정 이메일은 Android Keystore 키로 암호화해 기기에 저장하고, 앱을 열면 자동으로 세션을 확인합니다. 토큰이 만료되거나 서버에서 취소되면 다시 로그인합니다. 화면 위쪽에서 로그인 상태를 확인하고 **로그아웃 · 계정 변경**으로 이 기기의 세션을 종료할 수 있습니다. 사진은 Supabase의 비공개 `sales-cards` 버킷에, 기관·담당자·명함 필드는 기존 `scheduler` 테이블에 저장됩니다. 웹의 `/admin/sales/cards`에서 최신 명함을 확인할 수 있습니다. 저장에 실패하면 앱이 업로드한 사진 삭제를 시도합니다.

## 실행

Android Studio에서 `android-ocr-test` 폴더를 열고 `app` 구성을 안드로이드 기기에서 실행합니다. 최소 Android 6(API 23)이며 Google Play 서비스가 필요합니다.

명령줄 빌드:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME = 'C:\Users\jaspe\AppData\Local\Android\Sdk'
.\gradlew.bat assembleDebug
```

APK는 `app/build/outputs/apk/debug/app-debug.apk`에 생성됩니다.

## 앱 업데이트

기존 0.1.0 또는 0.2.0 앱에는 업데이트 코드가 없으므로 0.3.0 이상 APK를 한 번 직접 설치해야 합니다. 이후 새 버전이 배포되면 앱을 열 때 자동으로 확인하고 APK를 다운로드합니다. 안드로이드의 시스템 설치 확인과 최초 1회의 "이 앱에서 설치 허용" 설정은 사용자가 직접 진행해야 합니다. 화면의 **업데이트 다시 확인** 버튼으로 실패한 다운로드를 재시도할 수 있습니다.

업데이트 파일은 이 저장소의 공개 GitHub 릴리스에서만 내려받습니다. 배포할 때는 버전 번호를 올리고, 같은 서명키로 APK를 빌드한 후 `android-ocr-v0.4.1` 형식의 태그를 가진 릴리스에 `wise-card-ocr-test.apk`라는 이름으로 첨부해야 합니다. 앱은 릴리스의 SHA-256 해시와 APK의 패키지명·버전 번호를 검증합니다. 이 테스트 앱은 현재 개발 PC의 디버그 서명키를 사용하므로 향후 업데이트도 같은 PC의 서명키로 빌드해야 기존 앱 위에 설치됩니다.

## 권장 비교 방법

인쇄 명함 10장, 인쇄·손글씨 혼합 10장, 손글씨 메모 10장을 같은 조건으로 촬영합니다. 각 이미지마다 기관명·이름·전화·이메일의 정확 여부, 직접 수정한 필드 수, 표시된 OCR 시간을 기록합니다.

# Schedule · 면접·영업·학교 관리

지원자 면접 예약과 관리자별 면접·영업, 명함, 학교 배정을 관리하는 웹 서비스입니다. 명함 촬영과 기기 내 OCR에는 별도의 Android 앱을 사용합니다. 웹은 Next.js 16 App Router, React 19, TypeScript, Tailwind CSS 4, Supabase로 구성되어 있습니다. 엑셀 가져오기·내보내기에는 ExcelJS를 사용합니다.

관리 화면은 데스크톱과 모바일 폭에 맞춰 표시되며, 공개 예약 링크에는 공유 이미지·제목과 파비콘이 적용되어 있습니다.

## 사용자와 권한

| 사용자 | 사용할 수 있는 기능 |
| --- | --- |
| 지원자 | 열린 면접 시간 예약, 예약 조회·변경·취소, 선택적 이력서 첨부 |
| 최고관리자 (`admin`/`super_admin`) | 본인 면접·영업·명함 관리, 전체 학교 목록과 배정 관리, 강사별 현황 조회, Google Calendar 연결 |
| 중간관리자 (`instructor`) | 전용 예약 링크로 접수한 본인 면접, 본인 영업·명함, 자신에게 배정된 학교 관리 |

최고관리자의 **면접 관리·영업 관리·명함 관리** 화면은 본인 데이터만 보여줍니다. 다른 중간관리자의 현황은 **강사 관리**에서 확인합니다. 관리자의 페이지 접근과 데이터 읽기·쓰기는 서버 인증 및 Supabase 권한 정책으로 검증합니다. 모든 관리자 화면에는 로그아웃이 있습니다.

## 면접 예약과 관리

- 지원자는 이름과 전화번호로 예약을 시작합니다. 관리자가 연 날짜와 시간만 표시되며, 예약 저장 시 서버와 DB에서 가용 시간을 다시 확인합니다. 시간은 한국 표준시 기준 30분 간격으로 관리합니다.
- 이력서는 선택 사항입니다. PDF, DOC, DOCX, JPG, PNG, WebP 파일을 최대 5MB까지 첨부할 수 있으며 관리자가 내려받을 수 있습니다. [이력서 저장소 설정](docs/resumes-setup.md)을 참고하세요.
- 지원자는 `/application`에서 이름·전화번호로 기존 예약을 조회하고 확정된 예약의 일정을 바꾸거나 취소할 수 있습니다. 이 조회는 휴대전화 소유 확인을 대신하지 않습니다.
- 관리자는 `/admin` 달력에서 **본인의 면접**과 날짜별 열린 시간을 확인하고 조정합니다. 예약은 확정·취소·채용 상태로 관리하며, 채용한 지원자는 채용 목록으로 이동하고 채용 처리자를 기록합니다.
- 중간관리자는 각자의 전용 예약 링크를 지원자에게 전달합니다. 예약과 시간 관리가 관리자별로 분리됩니다.
- 최고관리자만 본인의 Google Calendar를 연결하고 본인 면접 예약을 동기화할 수 있습니다. 예약 동기화 대기열과 재시도 기능이 있으며 중간관리자 면접은 최고관리자 캘린더에 넣지 않습니다. [Google Calendar 설정](docs/google-calendar-setup.md)을 참고하세요.

## 강사 관리

최고관리자는 `/admin/members`에서 강사 계정 요청을 승인하고, 면접 예약·채용 이력과 중간관리자별 영업·학교 현황을 확인합니다. 중간관리자는 본인이 면접을 보고 채용할 수 있습니다. 채용강사는 관리자 로그인 화면에서 권한을 요청할 수 있으며, 최고관리자가 채용 기록을 확인해 승인해야 중간관리자 권한이 부여됩니다. 이메일 확인 대기 단계는 사용하지 않습니다. 승인 전에는 관리자 자료를 볼 수 없습니다.

강사 카드에는 누가 누구를 채용했는지, 본인 면접 현황, 영업 기관 현황, 배정 학교와 최근 접촉 내용을 표시합니다. 최고관리자는 강사별 영업 및 학교 데이터를 필요한 컬럼으로 선택해 엑셀로 내려받을 수 있습니다.

## 영업 관리와 명함 관리

- `/admin/sales`의 내 기관 목록은 담당자, 이메일, 방문일, 제안서 상태, 반응, 최근 업데이트를 보여줍니다. 기관 유형·지역·담당자 검색, 페이지당 25개 목록, 필요한 컬럼을 고르는 엑셀 다운로드를 지원합니다.
- 기관이나 명함을 선택해 첫 상담을 기록합니다. 후속관리에서는 기관명·담당자·이메일, 방문일·지역, 제안서 제출, 반응, 접촉 방식, 업데이트 날짜, 특이사항을 갱신합니다. 기존 특이사항은 읽기 전용으로 확인하고 새로 입력한 내용은 활동 기록으로 남깁니다.
- 기관 상세페이지에는 현재 상태와 활동 타임라인이 있으며 기존 활동을 수정하거나 삭제할 수 있습니다. 내용 변화가 없는 후속 저장은 중복 타임라인으로 표시하지 않습니다.
- 기관 삭제 전 확인 창에서 연결된 담당자·명함 사진·활동·미팅·제안서 등 영향을 받는 데이터를 보여주고, 확인 후 관련 데이터를 함께 정리합니다. 활동 삭제에도 확인 절차가 있습니다.
- `/admin/sales/cards`는 본인이 등록한 명함 목록입니다. 명함 사진과 추출 정보를 확인하고 활동을 기록할 수 있습니다. 모바일 웹의 **새 명함 등록**은 Android 앱을 열며, PC에는 앱 사용 안내와 APK 설치 링크를 표시합니다.
- Android 앱은 사진 촬영·앨범 선택, 자동 자르기와 보정, Google ML Kit 한글·영문 OCR, 필드 후보 추출과 직접 수정, 선택 영역 재인식을 제공합니다. 확인한 기관·담당자·사진은 로그인한 관리자의 영업 작업공간에 저장하고 저장 확인번호를 표시합니다. 앱을 열면 새 APK를 확인하고 다운로드할 수 있으며 Android 설치 확인은 사용자가 진행합니다. 자세한 빌드·업데이트 방법은 [Android 명함 앱 안내](android-ocr-test/README.md)를 참고하세요.
- 브라우저 등록 화면에도 OCR과 수동 수정 기능이 있습니다. 선택적 Google Vision 설정은 [설정 안내](docs/google-vision-setup.md)를 참고하세요. 영업 테이블과 Storage 설정은 [영업관리 설정](docs/sales-management-setup.md)에 정리되어 있습니다.

## 학교 관리

최고관리자는 `/admin/schools`에서 학교 엑셀의 **학교목록** 시트를 업로드해 목록을 추가·갱신하고, 광역지역·지역·학교급·담당자·학교명으로 검색합니다. 최고관리자 본인을 제외한 승인된 중간관리자에게 선택 학교 또는 검색 결과 전체를 배정할 수 있습니다. 배정 이력은 유지됩니다.

| 탭 | 표시 기준 |
| --- | --- |
| 전체학교 | 추가제안·제외학교로 분류되지 않은 학교 |
| 진행중 | 활동 기록이 있고 추가제안·제외학교로 분류되지 않은 학교. 최신 활동 순 |
| 추가제안 | 수업 완료 뒤 새로운 제안을 위해 따로 분류한 학교 |
| 제외학교 | 당분간 관리 목록에서 제외한 학교 |

분류된 학교는 전체학교와 진행중에 중복 표시되지 않으며 분류를 다시 바꿀 수 있습니다. 중간관리자는 **내 배정학교** 목록에서 학교 담당자 이름·이메일·접촉일을 확인하고 학교명을 눌러 상세페이지로 이동합니다. 후속관리에는 학교 대표전화와 별도로 담당자 전화번호를 기록할 수 있습니다. 제안서·반응·접촉 방식·특이사항 등은 명함 없이 기록하며, 상세페이지 활동 타임라인에서 이전 기록을 수정·삭제할 수 있습니다.

최고관리자는 강사 관리 화면에서 담당자별 학교 활동과 최근 접촉 내용을 확인할 수 있습니다. 학교 관리의 엑셀 다운로드는 대상 탭을 여러 개 선택해 시트별로 만들고, 필요한 컬럼도 선택합니다. 학교를 체크해 삭제할 때는 배정·접촉·활동 수정 이력 등 영향을 받는 자료를 확인 창에 보여준 뒤 연계 데이터를 함께 삭제합니다.

## 주요 경로

| 경로 | 내용 |
| --- | --- |
| `/login`, `/booking`, `/application` | 지원자 예약 시작, 일정 선택, 예약 조회·변경·취소 |
| `/admin/login`, `/admin/signup` | 관리자 로그인과 강사 권한 요청 |
| `/admin` | 본인 면접 달력·시간·예약·채용 관리 |
| `/admin/members` | 최고관리자의 강사 승인 및 강사별 현황 |
| `/admin/sales`, `/admin/sales/[id]` | 내 기관 목록과 상세 활동 |
| `/admin/sales/cards` | 내 명함 목록과 등록 안내 |
| `/admin/schools`, `/admin/schools/[id]` | 학교 목록·배정·분류와 학교 상세 활동 |

## 개발 환경

Node.js 22 이상과 pnpm이 필요합니다. 저장소의 `management` 디렉터리에서 실행합니다.

```sh
pnpm install --frozen-lockfile
cp .env.example .env.local
pnpm dev
```

Windows PowerShell에서는 `cp .env.example .env.local`을 그대로 사용할 수 있습니다. 브라우저에서 `http://localhost:3000`을 엽니다. `.env.local`에는 사용하는 Supabase 프로젝트와 Google OAuth 설정 값을 입력합니다. 서버 전용 키는 클라이언트 공개 변수로 넣지 마세요.

| 환경 변수 | 용도 |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase 연결 |
| `SUPABASE_SECRET_KEY` | 서버에서 사용하는 Supabase 관리 API |
| `APP_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Google Calendar OAuth |
| `CALENDAR_TOKEN_KEY`, `CALENDAR_SYNC_SECRET`, `CRON_SECRET` | 캘린더 토큰 암호화·동기화 작업 인증 |
| `GOOGLE_VISION_API_KEY` | 선택적 브라우저 OCR 보조 기능 |

새 DB에는 `supabase/schema.sql`부터 필요한 마이그레이션을 적용해야 합니다. 기존 운영 DB에는 이미 적용된 SQL을 무작정 재실행하지 말고 [영업관리](docs/sales-management-setup.md), [Google Calendar](docs/google-calendar-setup.md), [이력서](docs/resumes-setup.md) 안내와 `supabase/`의 기능별 SQL을 확인하세요. SQL 파일을 저장소에 추가하는 것만으로 운영 Supabase에 자동 적용되지는 않습니다. 학교 초기 자료 예시는 `supabase/school-management-data.sql`에 있습니다.
